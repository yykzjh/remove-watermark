# 千张首轮去水印第二轮优化（2026-11-01）

尚未达到“千张全部一次正确通过”。本报告把自动验收、已知目标对照和实际图像真值分开统计；不通过放宽阈值、强行改判或多次生成后回填首轮计数来提高通过率。38,319张全量任务未提交。

## 本轮保留的改动

- 新增可选部署参数 `--quality-rectangle-guard`，CPU检查原信息面板多条可用边的明暗突变是否同向、位置一致。只对面积至少6%的已确认panel运行，照片边缘不虚构外部参照；必须同时有横边与竖边、全部可用边同号且强度相容，原图同位置未变的边不计。其他已知水印污染边界邻域时放弃该项判断。
- 该检查只会增加review，不会批准图片。依据保存在repair_rectangle_phase，连同边位置、局部对数明暗阶跃和支持比例进入返工反馈。旧纹理、接缝、内容变化和残留检查继续有效，模型解释及争议复核不能清除该警告。
- 残留定位出现过大/错误合并框时，最多进行一次全新完整结果扫描，预算至少1024，仍按同一框数、类别、坐标和面积上限校验。不裁切错误框、不把失败默认为空，不因重检为空直接撤销其他拒绝。
- 冻结0408.jpg复验从检验错误转为review，额外扫描0.493秒；原图和输出哈希未变，仍因水印判定分歧未批准。修复可用性不等于修好了去水印结果。
- Linux桌面和批处理CLI新增`--context`，将实测上下文系数传入任务；不增加批量页面的固定水印区域或框选参数。默认系数保持0.6，推荐启动命令显式选择本轮参数。
- 质量吞吐配方保留默认8卡、大输入batch1，并将已实测的小输入batch2写入配方；CLI/config中的`small_batch_size=0`仍表示继承主batch上限。所有布尔参数仍不传=false、传入=true，配方只显式选中所用功能。

## 复现与部署

开发和测试均在WSL2/Linux、uv环境进行。先本地commit/push，再开发机git pull同步。
SSH仅普通命令、少量状态；本轮用于人工诊断的5张小JPEG合计382,974字节，没有传输源代码包或批量图像。测试输入和输出均在开发机数据盘。

~~~bash
# 配方默认8卡；本次0/6/7被其他任务占用，显式使用1–5
bash scripts/launch-throughput-quality.sh --gpus 1,2,3,4,5 --load-parallelism 5 \
  --model "$HOME/.cache/watermark-models/models/Qwen--Qwen-Image-2.1-Turbo/snapshots/master"

# WSL客户端：仅预填，不会自动提交任务；输入输出路径由用户在开发机准备
UV_PROJECT_ENVIRONMENT="$HOME/.cache/uv-envs/remove-watermark" \
uv run --no-sync watermark-studio --ssh-host cdu_dev \
  --preserve-background --quality-check --quality-cross-review --quality-auto-retry \
  --quality-batch-size 2 --first-pass-mode complete --context 0.45 \
  --input-resolution 1024 --repair-blending harmonic

# 固定完整检验对照，不改写任何已有图像
# 先停止推理服务，避免占用相同GPU
uv run --no-sync python scripts/benchmark-verifier-known-source.py \
  --source-job d8c4ad05f5f74da6af3e935e09e20ec7 \
  --controls /mnt/sdb/zjh/baidu-download/1mQf6F6g-20261031/adversarial-duel-controls-v1 \
  --profile 4b-bf16 --gpus 1,2,3,4,5 --quality-batch-size 2 \
  --rectangle-guard --tag fresh-tag
~~~

CLI中quality_rectangle_guard默认false；质量配方显式启用。大输入batch1、小输入batch2、window4；concurrency是全局在途原图数，本次5卡建议20，默认8卡建议32。没有根据该数值放宽检查门槛。

272项Linux测试通过，Ruff无错误。聚合机器结果见[JSON](first-pass-round2-2026-11-01.json)。仍有已知误拒和暗框漏检；本轮不能承诺千张零缺陷一次通过。
