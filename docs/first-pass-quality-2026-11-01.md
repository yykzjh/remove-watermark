# 优先首轮完成的去水印策略（2026-11-01）

目标是提高从原图生成的第一份候选的完成度，独立检验只负责把关，返工作为少量失败项的后手。首轮统计只计新生成候选；已有结果复检和后续返工不算首轮通过。

## 自动首轮策略

`first_pass_mode` 是任务参数，桌面、CLI、API 均可设置：

| 值 | 行为 |
| --- | --- |
| whole | 兼容原整图生成；原图保护开启时只合成检测位置 |
| focused | 从每张完整原图自动检测任意位置覆盖层，按覆盖层分别生成、合成 |
| thorough | focused 加有条件的源图细节定位，改善全图缩小时遗漏的细小防伪码 |

focused/thorough 必须显式启用 preserve_background。所有 bool 仍是不传=false、传入=true；库默认 whole 不隐式改变布尔配置。批量没有固定公共区域或手动框选参数。

thorough 在原图最长边超过1400、且全图尚未检测到小覆盖层时，扫描四个重叠象限，覆盖整张源图。只补充面积不超过整图3.5%、不与已有组相连的小覆盖层，避免分块把大面板拆碎后扩大重绘。扫描异常明确失败，不套用固定角落。

每一组始终取自原图，避免上一块生成内容污染下一块。大面板使用选择的输入预算，小覆盖层使用至多512预算的可读裁切。512不是把完整大图缩到512：它针对较小原图视野，细小字符相对更清楚。它保留按尺寸分组、每卡窗口、OOM拆批机制。

首轮可能有多个覆盖层模型调用，不能表述为只运行一次扩散推理。记录 model_inferences（逐图编辑输入数，并非GPU批次数）、model_input_budgets、source_detail_views、source_scene 和实际加载的 code_revision。

## 防止自然度和内容保持退步

局部提示词依据覆盖层周围真实材质，完整原图同时提供受限场景类别 outdoor/document/indoor/unknown。票据、证书在衣物上的照片按document处理；水印里的房子图标或文字不能作为补草地的依据。原本可见的纸张边缘、布料、文字、人物轮廓、工程线条保持；不凭空编造被完全遮住的读数。

早期开发样例曾在票据下补出草地，已废弃该提示词；当前中性提示词已在同一原图的压缩预览中保住纸张和牛仔布背景。不能仅凭自动通过率宣称材质正确。

合成时以不可变原图和所有水印外邻域作为明暗参考，排除其他水印，避免把另一面板的颜色带进修补区。确认的覆盖层核心完全不透明替换，只在额外安全外沿平滑回到原图，减少明显方框阴影。JPEG重新编码仍会有量化差异。

检验的残留扫描、边界明暗台阶、纹理塌缩、可见内容变化等标准均未降低。模型说明与数值保护有分歧仍保留review；不得以说明“看不出问题”覆盖拒绝。

## 独立抽样与完整流程

128张为种子20261101的独立抽样，排除原64张开发集；比较前未用这些样本调提示词，两个策略使用相同文件名/种子规则、同一输入、全新输出。两组关闭自动返工和争议改判，标准相同。

| 模式 | 首轮通过 | 首轮待复核 | 总耗时秒 | 尺寸不符/处理错误/检验错误 |
| --- | ---: | ---: | ---: | --- |
| whole-1024 | 108/128（84.375%） | 20 | 288.706 | 0 / 0 / 0 |
| thorough-1024 | 118/128（92.188%） | 10 | 313.942 | 0 / 0 / 0 |

首轮通过增加7.8125个百分点，待复核数减半；总耗时增加8.74%。成对统计：107张两组均通过，11张由review转passed，1张由passed转review，9张两组均review。不能隐去新版退步的0018。

新版有233个编辑输入（122个1024、111个512），96个额外源图视图。它的编辑输入数量接近原策略122个的两倍，但局部小预算和多卡调度使本次wall time只增加约8.7%。峰值分配41957MiB。不能将编辑输入数当作实际GPU批次数。

人工压缩预览复核：
- 新版退步0018确实残留最底部一行小防伪码；检验正确保留review，未豁免。
- 改善0074的信息板与细小防伪码已清除，测量轮的原可见读数仍在，修补延续轮子与泥土。
- 开发样例054在中性场景提示下保住纸张和牛仔布，废弃了早期补出草地的结果。

这只是少量压缩预览，不是对128张原尺寸结果的人工逐张验收。上述率是当前严格自动检验的观测通过率，不能当作经人工标注的真实准确率。

首轮对照实际加载23e68d9。随后512a23b补齐“返工进入自动局部模式后仍沿用中性材质提示和场景条件”的分支，不改变此次完整原图首轮路径；新增回归覆盖后156项Linux测试通过、Ruff通过。完整流程在512a23b上另测。

### 64张完整流程

相同原64张开发样本，原图保护、普通harmonic、1024首轮输入，检验768/batch2/4细节，自动返工最多3次尝试，开启争议复核。此次实际加载512a23b。

| 模式 | wall time秒 | 首轮通过/待复核 | 实际返工次数 | 最终通过/复核 | 尺寸不符/处理错误/检验错误 |
| --- | ---: | --- | ---: | --- | --- |
| 新策略仅去水印 | 141.744 | 未检验 | 0 | 未检验 | 0 / 0 / 0 |
| 新策略+完整检验/有限返工 | 190.083 | 62 / 2（96.875%通过） | 3 | 63 / 1 | 0 / 0 / 0 |

本次完整流程为仅去水印的1.341倍，增加34.1%，没有超过2倍目标。逐项quality_seconds是多卡累加，不是wall time增量。4次问题说明均成功，3次返工使用实际反馈，0次实际争议复核，峰值分配41957MiB。

对照[此前相同64张流程](cross-review-2026-11-01.md)：首轮55/64→62/64，返工13→3，最终61通过/3复核→63通过/1复核；端到端189.555→190.083秒，单次观测接近。首轮本身做得更多：仅生成118.988→141.744秒，减少返工抵消了新增源图定位/局部生成的大部分总成本。此64张参与过开发，不能替代上方128张独立对照，也不能以两次独立运行的0.528秒差值声称稳定性能变化。

最终054仍为残留文字判断分歧，说明模型未确认可见缺陷；保持review，没有为了全绿而删除真实文字或放宽标准。首轮失败2/64不是零，完整数据仍需要保留独立检验和有限返工的安全后手。

机器可读指标见[验证记录](first-pass-validation-2026-11-01.json)；完整逐张依据保留在开发机任务目录和 first-pass-holdout-neutral-v1/results.jsonl。两个profile顺序运行一次，存在算子缓存、编译和共享资源波动，不能把单次耗时外推为万张或8卡承诺。

## 复现

~~~bash
# 服务，默认配方是8卡；此处显式只使用空闲的1–5
bash scripts/launch-throughput-quality.sh --gpus 1,2,3,4,5 --load-parallelism 5

# WSL客户端，预选配置，不自动提交任何任务
uv run --no-sync watermark-studio --ssh-host cdu_dev \
  --preserve-background --first-pass-mode thorough --input-resolution 1024 \
  --quality-check --quality-batch-size 2 --quality-auto-retry --quality-cross-review

# 真正首轮对照：关闭返工与争议改判，相同输入，必须使用新tag
uv run --no-sync python scripts/benchmark-first-pass.py \
  --tag holdout-neutral-v1 --subset holdout --images 128 \
  --profiles whole-1024 thorough-1024
~~~

输入/输出均在开发机，默认输出原图宽高、文件名和深层目录层级；附带非图像原样复制。不会自动提交38,319张全量任务。

自动检验是有限模型与规则的观测，人工压缩预览也是抽样；被水印完全遮住的真实内容无法从单张照片唯一恢复，不能保证所有照片无误。
