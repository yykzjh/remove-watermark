# 整图直接处理纠正与对照

用户要求的路径为：完整原图 → 编辑模型 → 完整生成结果 → 按完整输出尺寸重采样。客户端批量及单张自动模式不再展示历史裁切策略或局部原图合成开关；自定义区域模式继续局部处理。整图模式的自动返工从原始完整图像重做，不切换至自动裁切。

旧 complete 策略由 Qwen3-VL 全局定位、局部补查、检测框扩边、加上下文裁切、分别编辑并合成组成。旧千张报告 947/1024 是这种策略的自动验收数，不能代表整图直接处理，更不是人工确认正确率。

CLI/API 显式选择 focused/thorough/complete 与 preserve_background 仍可复现历史对照。whole 加 preserve_background 是整图生成后局部合成，必须与 whole_direct 区分；直接整图需 scope=full_image、first_pass_mode=whole、preserve_background=false。

## 可复现参数

服务配方仍默认全部8卡，当前仅使用未被他人任务占用的1–5卡。B2实验在质量服务脚本末尾追加 --batch-size 2；该参数控制每卡单次前向最大图数，不代表全部图像都能实际凑两张。拆批、首次编译、独立检验、写入均计入端到端时间。

客户端不指定 --preserve-background，选用 --first-pass-mode whole：
    
    UV_PROJECT_ENVIRONMENT=/home/yyk/.cache/uv-envs/remove-watermark \
      uv run --no-sync watermark-studio --ssh-host cdu_dev \
      --quality-check --quality-cross-review --quality-auto-retry \
      --quality-batch-size 2 --first-pass-mode whole --whole-prompt-profile fidelity --input-resolution 1024

客户端不会自动提交全量数据。布尔参数均未指定为false、指定为true。历史桌面裁切启动参数仅作兼容解析并在日志说明不应用于当前自动模式；历史实验改用watermark-batch或API。

## 验证边界

整图路径的Linux测试通过，包括每图只有一个完整参考、禁止调用区域定位/上下文裁切/局部合成、输出原尺寸、每图独立输入、整图返工路径、保留自定义区域功能。Ruff通过。

质量检验标准保持原值。不能因生成模型会改动非水印像素就自动豁免outside_repair_change。纯重采样也可触发该检查，但初步6张对照中，生成结果相对重采样基准仍有较多变化，不能仅用重采样解释告警。此项属于定位问题的开发探测，不是整体质量验收。

B2上限下，整图89张实际全部B1，40张所在worker请求出现OOM回退（不是40次独立OOM事件）；峰值分配44080MiB。裁切组50个编辑输入参与B2，其余117个B1，峰值44227MiB。后续整图提示词对照恢复大输入B1，避免反复试探不适合当前显存的B2。

整图89张全部触发水印外变化，另有边界11、纹理8、矩形相位1（可重叠）。VLM自身给71张通过、18张复核，不足以豁免像素和自然度检查。两个小预览样本中，一张现场测量照片出现全图明暗/色调变化；保留复核合理。不能把89张待复核全算作真实缺陷，也不能全算误报，更不能降低阈值让它们通过。
