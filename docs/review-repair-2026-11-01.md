# 两张待复核图的修补与检验优化（2026-11-01）

第一张门栏照片确有旧水印轮廓形成的方形暗影；第二张挖掘机照片没有发现相同缺陷，旧检验把真实机械字样误报为数字水印。本次修复了明暗融合，加入不能被 VLM 通过判断覆盖的阴影/纹理检查，推荐独立检验模型。未降低验收条件。

## 两张图的具体分析

- 010.jpg，3264×2448：左柱约 y=0.572 有横向明暗台阶，左下地面约 x=0.392 有矩形边界。原蓝灰信息面板和右下相机代码已去掉，但生成区颜色与原图不一致，仅边缘羽化不能消除整个低频暗框。门上的蓝白警示牌是实物，必须保留。
- 057.jpg，1707×1280：未见明显残留或方框。SDLG、E61351、EFQM、A199 等是机械本体上的标识，不能当水印删除。resident 后端在整图、接触表、独立细节三种观察方式均误报；独立 Qwen3-VL-4B-Instruct 在相同实验均通过。

两张最终真实推理均通过严格 v5 检验，无局部变化/阴影/纹理报警，输出保持原分辨率，测试前后原文件 SHA256 不变。单独两张冷态任务21.366秒，不能与不同缓存状态的历史任务直接作性能比较。

## 实际修改

1. 默认 repair_blending=harmonic：只从所有水印区域外的原图和生成图估计 RGB 差异，以最高512参考网格多尺度调和延拓到水印区，再合成羽化。被水印覆盖的颜色不参与参考，不改变图像几何。保留 feather 供对照，桌面“修补明暗衔接”和 CLI --repair-blending 可选。无新依赖。
2. 修补边界检查：沿自动检测区域查连续矩形色差/亮度台阶；检测阈值保持严格，用原图采样像素证据排除原本已有的真实边缘。
3. 修补纹理检查：拦截修补区域内部的清晰度骤降、平涂或长段纹理消失；中位颜色区分真实不同材质，原图已存在的模糊不作新缺陷。
4. 细节视图优先覆盖完整原水印区域，小区域先，另附变化与结构细节；独立放大图代替拼成一张接触表。有限4个细节仍不覆盖所有像素。
5. 推荐启动脚本默认 independent 检验，额外加载4B VLM；resident 仍可显式选择。检验 OOM 在释放 traceback 持有张量后拆批，记录 quality_oom_splits，不将异常当通过。
6. 同样未通过的返工候选，先保内容/局部变化/自然度，再在其余条件相同时优先残留扫描明确为空的候选；不会据此把 review 改成 passed。所有返工从原图开始，不累积改画。

## 严格控制实验

最终35个样例，24个坏例全部拒绝，11个预期正常或观察合理例全部通过，无检验错误；review_version=2026-11-01.boundary-texture-v5。

坏例含保留原水印、淡字残留、仅去文字仍留底板、平色填块、局部人体模糊、边缘移位、替换小块头部、真实旧矩形暗影，以及修补区内部模糊。好例含已知真值的合成水印完整去除、JPEG/缩放、真实警示牌/机械标识；11例中1例为用户和人工观察合理的旧057，不能把它表述为隐藏区域有真值证明。

开发中暴露过的盲点也保留记录：原 VLM 和额外一次局部自然度 VLM 都漏掉内部模糊，因此取消无效额外调用，采用实际能拦截的 CPU 纹理检查；最初边界检测误报原本的真实边缘，改用原图像素来源证据；最初均值颜色将黑白机械标识与水面混淆，改用中位颜色/持续纹理消失。没有为通过测试降低台阶阈值或按文件名放行。

## 64张混合实拍端到端耗时

同一64张输入、GPU1–5、每卡一个主模型、FP8 transformer/BF16、动态投影编译、batch_size=1、window=4、检测batch2、无VAE tiling；输入预算1024，输出原始尺寸；两组均开启原图保护和 harmonic 合成。采用768检验、batch2、4细节、最多3次尝试，计入全部返工。两组按顺序执行，服务已ready；脚本标签baseline-hot不保证所有形状均预热，所以比例是本轮观测，非严格无编译开销的长期比值。

| 模式 | 总耗时秒 | 处理成功 | 检验通过/待复核 | 尺寸不符 | 检验错误 | 检验OOM拆分 |

总耗时1.586倍，增加58.6%，符合本次样本小于2倍目标。新增14次返工，1张达到3次上限仍待复核，绝不报全通过。峰值分配42108 MiB；指标为窗口/进程峰值，不是所有卡显存求和。

这不是8卡或上万张完整运行的耗时承诺；64张中有4张判断无水印，图片复杂度、输入形状、首次编译、GPU共享和返工比例都会影响实际吞吐。两组服务均已加载独立检验模型，所以此表隔离的是任务中检验/返工开销；不包含独立模型部署加载时间和额外驻留显存成本。

扩展样本054为纸质单据照片，首轮遗漏右下极小防伪码，后续定位回传已找到该组。其输出仍被检验拒绝，保留 review。64张测试为0623298功能版本；后续b7fb041只调整同样拒绝结果间的候选排序，不修改检验标准，额外单图实测选择第2次候选，扫描残留框为空、水印外变化疑点0，但 VLM 仍不通过，最终仍为 review（3次尝试）；冷态单图总50.716秒，含新形状编译，不能用作热吞吐估计。

## 复现和部署

代码在WSL2、uv环境开发，经 Git push / 开发机 git pull 同步。所有原图、缓存生成图、完整输出与检验记录保留开发机数据盘；仅按用户授权回传少数 <=96 KiB 预览和有界 JSON。GPU0/6/7为其他任务占用，本次部署显式用1–5；脚本默认仍全部8卡。

~~~bash
bash scripts/launch-throughput-quality.sh --gpus 1,2,3,4,5 --load-parallelism 5 \
  --model /home/zjh/.cache/watermark-models/models/Qwen--Qwen-Image-2.1-Turbo/snapshots/master

# WSL桌面：布尔参数均显式打开，不自动提交任务
uv run --no-sync watermark-studio --ssh-host cdu_dev --preserve-background \
  --quality-check --quality-auto-retry --quality-batch-size 2 --repair-blending harmonic

# 在开发机复现吞吐对照；端口按当前服务设置
uv run --no-sync python scripts/benchmark-quality.py --url http://127.0.0.1:8765 \
  --tag new-repair-validation --images 64 --preserve-background --quality-auto-retry \
  --profiles baseline-hot quality-768-b2
uv run --no-sync python scripts/benchmark-review-cases.py --url http://127.0.0.1:8765 \
  --tag new-two-case-validation --strategies harmonic
uv run --no-sync python scripts/verify-quality-subtle.py --backend independent \
  --combined --run-label local-guard --repair-cases
~~~

独立控制实验会额外加载VLM，应选空闲GPU并给主服务预留显存；不要与满负载业务争抢同卡。所有布尔开关不指定=false，指定=true。界面可调整最大尝试；0为持续返工直至通过或取消，没有耗时上限。有限次尝试失败仍需人工复核。
