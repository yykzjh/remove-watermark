## 实测结果

### 单卡链路

开发机本地生成的合成图，单水印区域：
- 512 分辨率：提交至轮询完成约 5.06 秒。
- 1024 分辨率：工作进程记录 8.15 秒；包含轮询等待约 10.06 秒。
- 1024 测试后 GPU 显存占用 36438 MiB。
- 验证输出产生实际改变，修复区域及过渡边缘之外的 PNG 像素保持不变。

### 自动定位与七卡并发

运行 `uv run --no-sync python scripts/smoke-auto.py`：
- 8 张合成图：六种位置的信息栏、一张同时有信息栏与独立相机标识的图、一张无水印图。
- 自动定位长边 1280、修复分辨率 768、并发 7。
- 七个工作进程均实际取得任务；8 张图全部成功，包含 1 张“未检出水印”原样复制。
- 最终测试提交至轮询完成约 **14.31 秒**，包含目录扫描及轮询等待。
- 测试验证了移动水印区域覆盖率大于 95%、区域外像素保持、双水印识别、无水印文件字节一致。
- 测试后各卡占用 34484–34954 MiB（约 34 GiB）。这是完成后的显存快照，不是峰值测量。
- 自动框可能低估边缘，现采用按框尺寸外扩 6% 加图像尺寸 0.8% 的余量，并合并重叠框。

以上是功能验收，不能据此推断真实图像吞吐或七倍加速。实际图像尺寸、水印数量、检测分辨率与修复分辨率都会影响耗时。

## 本地测试与限制

- WSL Linux：11 项测试通过，Ruff 检查通过。
- GUI 已检查中文显示、提交参数、进度状态；主标题与窗口标题为“批量图像去水印”。
- 尚未处理用户的真实工地照片；需要用户在开发机准备后进行质量抽样验收。
- 自动检测仍可能漏检或误检。“未检出”不等于保证没有水印。
- 被完全覆盖的细节是根据上下文推断的补全，不能恢复未知真实细节。
- flex/compile 可选配置尚未做性能验证；默认七卡配置使用已验证的 SDPA。
- 项目实现数据并行；未接入针对单图的 TP/Ulysses/Ring 并行。

多卡机制参考：[Diffusers 官方分布式推理文档](https://huggingface.co/docs/diffusers/main/training/distributed_inference)。
