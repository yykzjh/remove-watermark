# 编辑侧纠正说明与独立验证复核（2026-11-01）

现在支持双向信息：检验侧把依据送入逐张返工；编辑侧也能为疑似实物文字误报提出说明，交给独立验证器重新检查。纠正初检误报需要新的图像证据和完整复验，不以模型自述代替标准。

## 启用

服务器继续使用 scripts/launch-throughput-quality.sh，默认独立 Qwen3-VL-4B-Instruct；没有新增权重。编辑侧复用 Qwen-Image-2.1-Turbo 已加载的视觉语言编码器，而不是声称扩散图像输出本身带有可靠文字解释。

~~~bash
# 桌面和批量CLI均显式打开，新布尔开关默认false
uv run --no-sync watermark-studio --ssh-host cdu_dev \
  --preserve-background --quality-check --quality-auto-retry --quality-cross-review \
  --quality-batch-size 2

uv run --no-sync watermark-batch /mnt/data/input /mnt/data/output \
  --concurrency 20 --preserve-background --quality-check --quality-cross-review \
  --quality-auto-retry --quality-batch-size 2
~~~

API: options.quality_cross_review=true。必须先启用quality_check，生产服务必须quality-backend=independent；同一模型不能充当两个独立意见。桌面有“编辑侧说明与独立复核”选项，以及复核、纠正和错误计数。

## 必须满足的条件

1. 原判定只有残留文字争议：自然度、可见内容保持都为true，uncertain=false；不存在任何明暗、纹理、填块或内容变化guard。
2. 至多2个精确争议位置，面积/宽高有限，不接触已确认原水印及羽化范围。被水印遮过的真实内容未知，不能冒充可见原图证据。
3. 原图/输出在争议位置尺寸相同，像素差异符合严格JPEG噪声容限：模糊后MAE≤1、95分位≤3、差值>8的像素比例≤0.003。这里只证明内容得到保留，不证明它不是数字水印。
4. 编辑侧和独立验证侧分别检查实物载体、材质/透视、是否数字覆盖，均须建立证据且无不确定。
5. 独立验证器接收受限纠正假设、原图/结果局部，重新检查完整输出。水印清除和自然度必须通过，不能因纠正某块文字忽略其他位置。
6. 再次执行未设白名单的完整残留扫描，所有区域必须为空；即使扫描仍报已确认争议框，也不能自动忽略。

任何一步失败都保留原拒绝。主观解释不能豁免数值guard，未完成的扫描不能通过。

自由模型叙述可能误读品牌或臆测具体材质，所以只作审计数据；不会作为任意指令进入另一模型。实际提示使用固定语义、校验过的位置和原图证据。局部图中同时提供准确相对框，避免把完整图坐标误读为裁切图坐标。

模型JSON字段不全时，重新执行受语法约束的布尔判断，保留实际观察文字；不填入默认true。缺少可见依据不能成立纠正说明。

## 有限预算与记录

每张图整个返工生命周期最多实际争议复核1次。编辑侧有实物证据而验证侧不同意时，保留候选，只额外复检1次；仍不通过就retry_blocked=unresolved_physical_text_dispute并保留review/error，quality_max_attempts=0也不无限争辩或盲目擦掉真实文字。

quality.cross_review保存实际编辑记录、争议框、像素对照、两侧说明、整图复验与扫描、耗时；纠正后pre_cross_review保留原判定和依据，model_explanation.status=adjudicated。所有记录保留开发机。

summary.json和界面显示cross_review_attempts/corrected/errors，按当前实际事件计数，不把沿用最佳候选的旧记录重复计入。原有输出目录镜像、图像原始宽高/名称、非图像原样复制保持。

2个实物对照纠正成功，3个数字水印对照无误放行。机械后部有部分文字原本被水印挡住，最初测试正确地被保护条件拦截，随后改用原图确实可见的臂杆文字；没有扩大允许区域或放宽阈值。

耗时不含权重加载，首个样本可能含算子预热。复核只用于极少数争议，不能把上述单次开销视为所有图像统一开销。真实对照脚本 scripts/validate-cross-review.py 在空闲GPU运行时仅加载两个视觉语言分支，避免与已驻留完整服务争抢显存。

Ruff通过，146项Linux测试通过，包括数字guard不能被双模型意见覆盖、全图扫描不忽略争议框、独立模型要求、格式恢复不能臆造字段、不可改写实物文字、无限模式不无限复核及事件去重。机器记录见[验证数据](cross-review-validation-2026-11-01.json)。

完整部署默认仍8卡。本次显式使用空闲GPU1–5，未干扰GPU0/6/7上的其他任务。没有启动38,319张全量任务，仍由用户在客户端提交。

## 64张完整流程回归

相同64张实拍输入，GPU1–5，1024输入预算、输出原尺寸，原图保护+harmonic，FP8/BF16动态投影编译、每卡batch1/window4。检验768/batch2/4细节，最多3次尝试，争议复核显式开启。服务ready后按顺序运行两组，baseline-hot标签不代表所有形状都完全预热。

| --- | ---: | ---: | --- | --- | ---: |
| 仅去水印 | 118.988 | 64 | 未检验 | 0/0/0 | 0 |
| 检验+依据+返工+争议复核 | 189.555 | 64 | 61/3 | 4/0/0 | 0 |

总耗时1.593倍，比仅去水印增加59.3%，保持本轮不超过2倍的目标。13次返工实际使用依据，16次说明成功且无说明错误。争议复核累计11.551秒是多卡逐项求和，不是wall time增量。峰值分配42108 MiB，无检验/说明OOM拆分。

本批4次争议均未建立实物文字证据，未作自动改判；三张最终待复核仍保留拒绝。受控实物误报对照2例纠正成功，不应混同为本批自然纠正数量。

上一版v6的单次观测188.054秒、同为61通过/3复核；本轮多1.501秒，但不是交叉重复实验，不能把该差值当作稳定的单一功能成本，也不是上万张或8卡耗时承诺。扫描样式、返工比例、编译和共享资源都会影响表现。
